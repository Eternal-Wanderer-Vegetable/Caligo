# 恢复办法(recovery-notes)

> K0 交付物。冻结于 2026-10-06(Asia/Shanghai)。
> 原则:先记录、再动手;能不修改文件就不修改文件;每次实验前明确退出与恢复路径。

## 1. 本轮(K0/K1 静态阶段)做了什么、没做什么

**做了(全部只读):**
- 读取工具链与 QQ 安装文件的元数据与 SHA-256。
- 枚举运行中 QQ 进程及其加载模块(Toolhelp/Process.Modules 级别的读取)。
- 解析候选模块 PE 导出表(静态,不写目标文件)。

**没做:**
- 未修改、未增删 QQ 安装目录内任何文件;未修改注册表;未修改 QQ 用户配置。
- 未启动、未停止、未注入任何 QQ 进程。
- 未备份任何文件(因为未计划修改任何文件)。

因此本轮的恢复动作 = 无需恢复(系统状态未被改变)。

## 2. K1 probe 实验阶段(即将进行)的恢复路径

probe 采用**运行时加载**(自有 Rust loader + bridge DLL),不落盘修改 QQ 安装:

| 情形 | 恢复办法 |
|---|---|
| probe 加载后实验结束 | 不做热卸载假设:bridge 不卸载,以**正常退出该测试 QQ 实例**收尾(计划 K1 第 7 条的默认收尾)。退出后 PID 消失即确认资源随进程回收 |
| QQ 崩溃(probe 触发) | 直接重新启动 QQ 正常使用;记录崩溃时间、当次 PID、实验步骤到 `local-evidence/`;若有 dump(通常在 `%LOCALAPPDATA%\CrashDumps`,具体路径待核验)一并归档 |
| loader 挂起/写入卡住 | loader 侧等待有超时;超时后放弃本次实验,仍以退出测试 QQ 收尾 |
| 误注入非目标实例 | 以正常退出该实例收尾;在 local-evidence 记录偏差 |

**明确不支持:**bridge 的安全热卸载在 K1 不承诺;若实验中需"去掉 bridge",唯一受支持方式是退出该 QQ 实例。

## 3. 未来若必须修改文件(当前不适用)

1. 修改前把目标文件复制到 `local-evidence/backups/<UTC日期>/`,并记录原文件 SHA-256 与大小。
2. 只修改冻结版本目录内、已在 manifest 登记的文件;一次实验只改一个文件。
3. 恢复 = 用备份副本覆盖回去,并复核 SHA-256 与原始值一致。
4. QQ 安装级整体恢复:使用官方安装包重装/修复;不手动拼装版本目录。

## 4. 配置与数据备份(待核验)

- QQNT 用户数据目录的准确位置未核验(候选:`%APPDATA%\QQ`、`%LOCALAPPDATA%\Tencent QQ` 等)。**在任何可能触及用户数据的实验前**,先核验实际路径并把下述内容备份到 local-evidence:
  - 登录态/票据缓存(整目录复制)
  - 聊天记录数据库(若实验可能损坏数据)
- 备份文件含账号数据,只留本机,不入库、不推送。

## 5. 实验实例退出标准流程(每次 K1+ 实验的收尾)

1. 通过 QQ 界面正常退出该测试实例(不用任务管理器强杀,除非已崩溃无响应)。
2. 用任务管理器/`Get-Process` 复核该 PID 已消失。
3. 在当次 local-evidence 记录:实验编号、PID、开始/结束时间、退出方式、异常。
4. 若该实例非本实验专用(误用),在记录中标注偏差并通知执行者。
